# Frequency-Domain Granger Causality

Research code for developing and evaluating Granger-causality methods in
simulated multivariate time series. The repository follows a chronological
experiment workflow, beginning with classical time-domain and spectral
Granger causality and extending to time-varying models, nonparametric spectral
estimation, VARX models, latent state-space models, and debiased statistical
inference for sparse networks.

> **Research status:** This is an active research repository, not a packaged
> library. Interfaces, experiments, and documentation may evolve as the
> methodology develops. Completed experiments are retained as reproducible
> historical records.

## Current scope

The codebase currently includes:

- pairwise and conditional time-domain Granger causality;
- parametric frequency-domain (spectral) Granger causality;
- VAR model fitting, diagnostics, stability checks, and order selection;
- sliding-window and recursive least-squares methods for time-varying VAR
  models;
- multitaper spectral estimation and Wilson spectral factorization;
- nonparametric spectral Granger causality;
- VARX simulation, estimation, order selection, and model-based causality;
- fMRI-like observation models based on hemodynamic response functions;
- Kalman filtering, Rauch--Tung--Striebel smoothing, and EM estimation for
  latent VARX state-space models;
- raw, debiased, likelihood-based, and empirically calibrated inference; and
- Monte Carlo evaluation of larger sparse directed networks.

The reusable source code is organized by topic:

```text

```

## Experiment progression

Experiments are numbered chronologically and should be read as a research
record. Each experiment generally introduces one primary methodological
change while preserving the preceding setup.

| Experiments | Main focus |
|---|---|
| 01--10 | Classical pairwise/conditional GC, spectral GC, diagnostics, order selection, and power spectra |
| 11--16 | Sliding-window and adaptive time-varying VAR/GC |
| 17--20 | Multitaper spectra, Wilson factorization, and nonparametric spectral GC |
| 22--23 | VARX confounding and fMRI-like observations |
| 24a--27 | Kalman smoothing, EM state-space estimation, and model-based GC |
| 28a--28e | VARX(p) debiased GC, finite-sample behavior, regularization, and order selection |
| 29a--29c | Latent VARX(p) simulation, smoothing, and EM |
| 30a--30f | Latent complete-data debiased deviance and empirical calibration |
| 31a--31z | Observed-likelihood inference, debiasing, robustness, shrinkage, and order sensitivity |
| 32a--32f | Sample-size studies and sparse 20-source network inference |

There is currently no `experiment_21`; the filenames in `experiments/` are
the authoritative experiment history.

## Setup

A recent Python 3 release is recommended. Create and activate a virtual
environment, then install the dependencies currently used by the code:

```bash
python -m venv .venv
```

On Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install numpy scipy pandas matplotlib openpyxl
```

On macOS or Linux:

```bash
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install numpy scipy pandas matplotlib openpyxl
```

Dependency versions are not yet pinned. Record the environment used for any
result intended for comparison or publication.

## Running experiments

Run scripts from the repository root so imports such as `src.gc` resolve and
relative output paths point to the correct `results/` directory.

For a small introductory experiment:

```bash
python experiments/experiment_01_pairwise_gc.py
```

For a spectral example that produces a figure:

```bash
python experiments/experiment_03_spectral_gc.py
```

Experiments define their parameters near the top of each script. Review those
parameters before running. In particular, later experiments can perform many
EM fits, bootstrap replications, or Monte Carlo runs and may require
substantial compute time. Some scripts include comments identifying reduced
settings suitable for smoke tests.

Depending on the experiment, outputs are printed to the terminal or saved as
PNG figures and CSV/XLSX summaries under `results/`. Existing result schemas
and filenames form part of the reproducible experiment record.

## Using the reusable modules

The modules in `src/` may also be imported directly when working from the
repository root. For example:

```python
import numpy as np

from src.gc.pairwise_gc import pairwise_gc
from src.simulation.var_generator import generate_var_data

A = np.array([
    [[0.5, 0.0],
     [0.4, 0.3]]
])
Sigma = np.eye(2)

data = generate_var_data(A, Sigma, n_samples=1000)
result = pairwise_gc(data, source=0, target=1, order=1)
print(result)
```

Function signatures differ across methods and continue to evolve. Consult
the relevant source module and its corresponding experiment for the
authoritative usage pattern.

## Reproducibility and development conventions

- Preserve random seeds and simulation/Monte Carlo settings.
- Treat completed experiments as historical records.
- Add reusable algorithms to `src/`; keep experiment scripts focused on
  parameters, orchestration, summaries, and outputs.
- Preserve existing public functions, output formats, and CSV column names
  when possible.
- For a new research idea, copy the closest experiment, assign the next
  chronological number, and change only what is needed to test the new
  hypothesis.
- Compare new results with the closest preceding experiment using the same
  metrics whenever practical.

Scientific correctness and comparability take priority over architectural
cleanup. See `AGENTS.md` for the full project conventions.

## Validation

The `tests/` directory does not currently contain an automated test suite.
Validation is performed primarily through the chronological experiments,
diagnostic checks, Monte Carlo summaries, and comparisons with earlier
experiments. When changing reusable code, run the closest relevant experiment
before and after the change and compare its numerical outputs.
